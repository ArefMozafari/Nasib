# Linux App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Nasib on Linux, a GTK 4 app in Rust that runs the shared `nasib-engine` and behaves like the macOS and Windows apps.

**Architecture:**
- A new `Linux/` Cargo crate (binary `nasib`) depends on `../Engine` only for shared constants and paths.
- It runs `nasib-engine` as a child process and parses its output lines.
- Pure logic (parser, catalog, selection, config, preferences, controller state, update compare, login file, appearance) lives in UI-free modules with tests. Thin GTK modules draw the window, Settings and the tray.
- `Linux/build.sh` builds and tests in an `ubuntu:22.04` Docker image and writes `.deb`, `.rpm` and `.tar.gz`.

**Tech Stack:**
- Rust 2024 (1.99) with `gtk4` 0.11 (GTK ≥ 4.6, features `v4_6`);
- `ksni` 0.3 for the tray;
- `notify-rust` 4 for notifications;
- `zbus` for the settings portal;
- `serde` / `serde_json`, and `ureq` 3 (rustls, proxy off) for the update check;
- `cargo-deb` and `cargo-generate-rpm` in the build image;
- UTM with Ubuntu 24.04 ARM for real-VPN checks.

**Spec:** `docs/superpowers/specs/2026-10-25-linux-app-design.md`

## Global Constraints

- **Engine contract:** behavior matches `Engine/README.md`:
  - lines `trying:` / `connected:` / `failed:` with `<protocol>:<port>`, `phase:`, `tunnel down`, `nothing worked`, `search stopped`, `survey stopped`, `survey finished`, `search already running`, `windscribe-cli missing: <path>`, `down`;
  - the modes `--watch`, `--survey`, `--status`, `--catalog`;
  - Stop is the line `stop` on standard input; closing standard input stops the run.
- **Timings:** status every 3 s (`STATUS_INTERVAL`), watch every 60 s (`WATCH_INTERVAL`), 200 recent lines, update check at launch and every 24 h.
- **Strings:** copied exactly from `macOS/Sources/Nasib/Tooltip.swift`, the notification titles and bodies in `Engine.swift` and `UpdateChecker.swift`, and the Settings messages in `SettingsView.swift`.
- **State folder:** `nasib_engine::paths::Paths::for_current_user().state_directory`. Preferences go in `preferences.json` there: `autoReconnect` (default true), `notifiedUpdateVersion`.
- **Config:** `config.json` with keys `locations`, `rankBySuccess`, `protocolOrder`, `cities`. `locations` is omitted when unset, and `cities` is kept as loaded.
- **Install layout:** `/usr/lib/nasib/{nasib,nasib-engine}`, `/usr/bin/nasib` (a symlink), `/usr/share/applications/nasib.desktop`, `/usr/share/icons/hicolor/scalable/apps/nasib.svg` plus the three tray glyph SVGs.
- **Repo rules:**
  - full-word identifiers, no magic values (sizes in `layout.rs`, strings in `text.rs`);
  - comments above the code, as full sentences;
  - helpers defined above their callers;
  - one test file per source file under `Linux/tests/`, test names `should_...`.
- **Workflow:** commits are small and split by concern, in the house style (`feat(linux):`, `build(linux):`, `docs:`), with no attribution. Nothing is committed, pushed or downloaded (UTM, ISO) without the user's go-ahead.

## Review Focus

1. **The engine binary is missing next to the app, or not executable:** the window shows "Engine missing from the app bundle.", the buttons are disabled, and nothing crashes. Pinned in Task 4.
2. **No tray host** (stock GNOME without the extension): the window opens at launch, and closing it quits. Pinned in Task 8 with a test of the decision function.
3. **The portal is missing or replies with an unexpected value:** the app falls back to GTK's default theme. Pinned in Task 7.
4. **Quitting mid-survey:** dropping the engine process closes its standard input and does not kill it, so the engine finishes reconnecting. Pinned in Task 4.
5. **`--background` from autostart while an instance is already running:** no second window, no second tray icon. Pinned in Task 8 (the GApplication single-instance rule) and checked in the VM.

### Task 4: Engine process and controller

**Files:** `Linux/src/engine_process.rs` and `Linux/src/controller.rs`, with their tests. Plus `Linux/tests/support/stub-engine`, a POSIX script that prints lines, answers `stop` and reports when its input closes.

**Interfaces:**
- **`EngineProcess`:**
  - `EngineProcess::start(engine: &Path, arguments: &[&str], on_line: impl Fn(String) + Send + 'static, on_exit: impl FnOnce(i32) + Send + 'static) -> io::Result<EngineProcess>`;
  - `stop(&mut self)`, which writes `stop\n`;
  - `Drop`, which closes standard input and never kills the process;
  - `EngineProcess::run_once(engine, argument) -> String`, with a 30 s guard;
  - `engine_path() -> Option<PathBuf>`, the file next to `std::env::current_exe()` when it's executable.
- **`Controller`:** UI-free state that the UI observes through a callback:
  - `ConnectionState { Unknown, Down, Searching(pair), Connected(pair) }`;
  - `is_finding`, `is_surveying`, `engine_missing`, `cli_missing`;
  - `recent_lines: VecDeque<String>` (200) and `dropped_line_count`;
  - `handle_line(&mut self, line: &str) -> Vec<Notification>`;
  - `tunnel_dropped(previous, current) -> bool`;
  - `is_striped(index, dropped_line_count) -> bool`.

  It mirrors `macOS/Sources/Nasib/Engine.swift`, including setting `is_finding` on `tunnel down`.

Steps:
- [ ] **Step 1:** Write the tests:
  - `should_read_lines_until_exit`;
  - `should_send_stop_on_standard_input`;
  - `should_close_input_without_killing_on_drop` (Review Focus 4);
  - `should_report_no_engine_when_the_file_is_missing` (Review Focus 1);
  - the controller transitions for every line kind;
  - the drop detection cases ported from `EngineTests.swift`;
  - the stripes;
  - `should_notify_once_per_event_kind`.
- [ ] **Step 2:** Run the tests and watch them fail.
- [ ] **Step 3:** Implement. Lines reach the UI thread through `glib::MainContext::channel` (or `async_channel` with `glib::spawn_future_local`).
- [ ] **Step 4:** Run the tests and watch them pass.
- [ ] **Step 5:** Commit `feat(linux): run the engine and track its state`.
